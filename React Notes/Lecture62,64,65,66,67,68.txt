LECTURE 62: Hooks

Hook is a functionality like state management, handling complex logic etc etc. Basically hooks are used to hook onto the functionalities provided by React.

useState Hook:

Every hook is prefixed with the word "use".
Every component can maintain their own state. The state management feature is done by the useState hook.

Inside the useState hook, we must maintain:
1. state variable
2. state function

We define the useState hook with this command:
const [count, setCount] = useState(0);
where count is the name of the state variable and setCount is state function and useState(0) means that the initial state is 0.

This is the counter program.
const Counter = () => {

  return (

      }}>

  )
}

Now wherever we use the count state variable in the entire code, the value will be updated.

LECTURE 65:

STATELIFTING: Concept of defining the state variable inside the parent component and letting all / needed children of that parent acccess the state variable.

PROPS ARE ALWAYS PASSED FROM PARENT TO CHILDREN. But what if we want to pass the data from children to parent?
Suppose we have multiple children of the same parent, and if the children want to share state data in between themselves, then it will only be possible if one child can pass data to the parent which can then be accessed by the other child.

The simple way to do it is by not letting the child maintain and create the state and let the Parent do all that work, so we will now create and maintain the state inside parent. Here inside the App component.

<Card card1name={name} card1setName={setName}>

Creating the Card component in this way will enable us to set the names and mantain the names individually for all the children components.

We now updated the Card component to this:

const Card = (props) => {
  return (
    <div>
      <input type="text" onChange={(e) => props.setName(e.target.value)} />
      <p>{props.name}</p>
    </div>
  )
}

what this means is that whenever we enter any value inside the text box, the setName function will be called and it will maintain the state i.e. change the name.

This is the concept of Lifting State that means without defining the state variable inside child component, we define the state variable inside the parent component and this lets us access the state variable from any of the child components of that parent.

LECTURE 66: Conditional Rendering

We can do conditional rendering using these 4 cases:
1. if-else 
2. ternary operator
3. logical operator
4. early return

1. IF-ELSE CONDITIONAL RENDERING:

function App() {
  const [isLoggedIn, setLoggedIn] = useState(false);

  if (isLoggedIn){
    return (
        <LogoutButton>

        </LogoutButton>
    )
  }
  else{
    return (
      <LoginButton>

      </LoginButton>
    )
  }
}


2. TERNARY OPERATOR:

  return (
    <div>
      {isLoggedIn ? <LogoutButton /> : <LoginButton />}
    </div>
  )


3. LOGICAL OPERATOR:

  return (
    <div>
      <h1>Welcome to Noobie Godly's Website</h1>
      <div>
        {isLoggedIn && <LogoutButton />}
      </div>
    </div>
  )

This will render the logout button only if the person is logged in.


4. EARLY RETURN:

  if (!isLoggedIn){
    return (
      <LoginButton />
    )
  }

  return (
    <div>
      <h1>Welcome to Noobie Godly's Website</h1>
      <div>
        {isLoggedIn && <LogoutButton />}
      </div>
    </div>
  )

In this code, if the person is not logged in, then he will see only a login button and if the person is logged in, then he will see the heading and the logout button.

LECTURE 67: EVENT HANDLING 

 <button onClick={alert("I was clicked")}>
      Click Me
    </button>

This is called immediate invocation which means that when we define the onClick function like this, then we are rendering the alert along with the button element and that is triggering the onClick event and generating the alert. The better way to solve immediate invocation is:

    <button onClick={() => alert("I was clicked")}>
      Click Me
    </button>

This will not invoke the code present inside the onClick event directly.

We also use e.stoppropagation which means that the event will not move up in the phase, that means if we have multiple nested divs and all of them have an event defined and we dont want that event to propagate further in the DOM tree, then we will use the e.stoppropagation function.

LECTURE 68: USE EFFECT HOOK 

useEffect hook: from the prefix use, we can make out that this is a React hook and we can generate side effect using this hook. 

WHAT IS A SIDE EFFECT??
For example listening to music at a high volume for long time / scrolling through screen for a long time which causes problems is called side effect.

For example: One side effect can be whenever content of DOM is loaded, we can connect it to the DB.
OR whenever the page is rendered, we can fetch some API. 

Here loading of the page is an event and fetching some API is the side effect of that event.


first -> Side effect function / logic (this is the side effect that is triggered when a specific event occurs)
second -> Clean up function (for example cleaning up memory / free up space etc)
third -> comma separated dependency list (this is the list of events / entities anf after these events are fulfilled, the side effect function is called.)

    useEffect(() => {
    first
  
    return () => {
      second
    }
  }, [third])

There can be many types of useEffect variations.
